## Caso y controles previstos

Usar una petición cerrada de integridad de medidas: dos lecturas e intervalos
dados, conversión exacta de unidades, suma nominal/extremos y límites de precisión.
No adquisición externa, archivos, ejecución ni contacto. La petición, política,
oráculo, script y runtime deben quedar congelados antes de la primera inferencia.
Las fichas las elige el planificador, no el oráculo ni el operador. Un especialista
autónomo es admisible sólo si su carta y revisión satisfacen el mismo mandato.

Una sola ruta de PLANIFICACIÓN, sin ejecutar sus nodos: Engine.ensurePlan sobre
una base nueva de ensayo. Conservar explícitamente que la misión no se entrega
ni se declara COMPLETED. Máximo3reservas de planificación, un intento de calidad,
cero reparaciones de juez y máximo4invocaciones de proveedor (planificador+juez).
Modelo y esfuerzo se conservan: gpt-6-astra/ultra mediante Codex oficial, perfil
scoped-v1, fichas compact-json-v1, contexto lossless-json-v2, revisión
evidence-catalog-v1. Sin aumento de límites de contexto ni de presupuesto por fallo.

No se garantiza que tres llamadas basten. Si no bastan, se conserva el límite y
el resultado incompleto; no se añade otro intento para obtener verde. Cuota,
transporte, formato incorrecto o rechazo material terminan este ensayo para
diagnóstico. Una reserva no demuestra dispatch y un recibo no demuestra lectura
comprendida. Capturar sólo solicitud/respuesta pública del esquema y recibo,
sin conversación privada de razonamiento. Cada llamada debe estar ligada al
