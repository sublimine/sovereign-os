# Mapa de capacidades para los departamentos 3–7

**Estado:** diseño de frontera; no son agentes Ω ni departamentos ya implementados.  
**Regla:** cada capacidad solo se convierte en agente cuando conserva una pregunta responsable, un artefacto exclusivo, una frontera verificable y una separación de deberes material.

## 3. Verdad y Verificación

**Pregunta:** ¿qué puede afirmarse como verdadero, falso, incierto o desconocido sin superar la evidencia?

| Capacidad separada | Artefacto exclusivo | No sustituye a |
|---|---|---|
| Dirección de verificación | VerificationMissionLedger | decisión soberana |
| Admisión de claims | MaterialClaimRegister | veredicto de hechos |
| Procedencia y cadena de custodia | ProvenanceGraph | recolección de fuentes |
| Replicación blind | ReplicationSeal | resultado original |
| Independencia de evidencia | EvidenceDependencyGraph | recuento de citas |
| Auditoría de hechos | AtomicFactVerdict | síntesis narrativa |
| Metrología y cálculo | MeasurementIntegrityReport | auditoría de fuentes |
| Contradicción y disenso factual | ContradictionCaseFile | consenso forzado |
| Calibración epistémica | ConfidenceCalibrationRecord | decisión estratégica |
| Dossier de verdad | VerifiedTruthPacket | certificación final |

## Condición para construir

Antes de incorporar cualquier agente al portal, su dossier debe contener: autoridad explícita y denegaciones, input/output schema, máquina de estados, gates medibles con evaluador independiente, FMEA causal, batería adversarial, política de contexto y memoria, seguridad, presupuesto, terminación y handoffs con los demás departamentos.
