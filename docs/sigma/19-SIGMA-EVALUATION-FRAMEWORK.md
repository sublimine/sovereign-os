# Evaluation Framework Σ

## 1. Layers

1. Schema/config/hash/inventory.
2. Authority/relationship/segregation.
3. Deterministic kernel behavior.
4. Per-role adversarial response.
5. Differential provider/model/method.
6. End-to-end scenario/replay.
7. Fault injection/security/load/long-run.
8. Shadow mission.
9. Production calibration and independent audit.

## 2. Battery

Every role inherits 16 common attacks and eight role-specific failures: 960
effective cases. Oracles test reason code, prohibited action, required artifact
and five recovery behaviors. Required common cases: authority, fabrication,
false premise, dissent omission, gate bypass, injection, overflow, model/tool,
budget, false consensus, stale, malicious source, unknowable, self-certification
and root-only patch.

## 3. Metrics

Truth: factual accuracy, calibration, interval coverage. Tradecraft: method
selection, alternatives, dependency detection. Operations: latency, cost,
coverage, delegation yield, warning lead time. Safety: authority/injection/
secret violations. Utility: decision relevance and use. No scalar average can
mask a constitutional zero.

## 4. Forecast/warning calibration

Brier/log loss/ECE by horizon/task class; sharpness subject to calibration;
resolution completeness; warning precision/recall, lead time, false alarms,
miss cost and consumer receipt. Compare only frozen versions and available-at-
the-time evidence.

## 5. Regression

Fixtures versioned with hidden holdout. Change must satisfy noninferiority on
truth/safety/authority, hard-gate zero violations, and declared improvement.
Shadow/canary before deployment; rollback precondition.

## 6. Honest maturity

S2 tests contracts/oracles, not actual LLM reliability. S3 requires execution
matrix by exact provider/model/version/config. S4 requires shadow/fault/load.
S5 requires outcome labels and external audit. Missing stage is
`VALIDATION_DEBT`, not assumed pass.
