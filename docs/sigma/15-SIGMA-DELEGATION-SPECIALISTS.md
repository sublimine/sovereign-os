# Delegación y Especialistas Temporales Σ

## 1. Ontología

Capability = aptitud; Template = charter reutilizable; Role = accountability
permanente; Instance = ejecución con lease. Reutilizar template no comparte
contexto, memoria ni independencia.

## 2. Creation pipeline

```text
NEED → CAPABILITY GAP → REGISTRY SEARCH
→ REUSE/JOIN/MERGE or DERIVE TEMPLATE
→ CONFLICT/DUPLICATE CHECK
→ MODEL/TOOL/CONTEXT/COMPARTMENT ROUTE
→ POLICY AUTHORIZATION → SANDBOX → RUN/CHECKPOINT
→ SELF-CHECK → INDEPENDENT REVIEW IF MATERIAL
→ ARTIFACT → TERMINATE INSTANCE → RETAIN/RETIRE TEMPLATE
```

## 3. SpecialistMandate

Trigger, capability, one bounded mission, objective invariant, input/output,
context include/exclude, tools/permissions, model/effort, all budget dimensions,
max children/depth, deadline, verification, termination, memory TTL, sponsor,
classification and idempotency.

## 4. Proliferation control

Child default 0; normal depth ≤2, declared roles up to 3; exceptional R5 depth
4 requires Σ2/Σ4 + Ω20. Every child consumes parent reserve. Expansion >2×
replans. DuplicateWorkDetector compares normalized objective, capability,
evidence scope and schema. Scheduler joins, merges, cancels dominated branches
and garbage-collects orphan leases while preserving artifacts/audit.

## 5. Scale

Q0 0–5 specialists; Q1 3–20; Q2 15–60; Q3 40–150; Q4 80–300+ across shards.
These are envelopes, not targets. Verification capacity is reserved before
collection fan-out. If review queue cannot absorb output, backpressure stops
spawning.

## 6. Novel specialties

Domain is encoded as capabilities+constraints+evaluation. A novel role cannot
inherit Ω/Σ authority. Retain template only after valid outputs, zero policy
violations, recurring value and measured calibration; otherwise shadow/retire.
